1.0 Description

IBM Text-to-Speech Run Time Kit provides the speech synthesis engine and components necessary for applications to produce speech. The Text-to-Speech (TTS) Run Time Kit produces speech from recordings of units of human speech. These units (possibly phonemes, syllables, words, or phrases) are then combined (concatenated) according to linguistic rules formulated from analyzed text. When these recorded speech units are entire phrases or sentences, the output can be very natural, human-sounding speech.

The Speech synthesis engine and data include capability for a concatenative voice dataset representation as well as for computer synthesized voice representation known as formant synthesis. The concatenative voice is derived from a professional speaker, speaking a particular language and dialect and recorded at a particular sampling rate. When a client program changes languages, and it is performing concatenative synthesis, a new voice dataset may have to be loaded into memory from disk, if it is not already cached in memory from previous usage.

The system will automatically choose concatenative synthesis if a voice dataset is available for the language, voice, and sample rate that you select. For example, if you are using English at 8 kHz with voice 1 and U.S. English voice 1 concatenative at 8 kHz has been installed, then the system will automatically use concatenative synthesis. Otherwise, the system will use formant synthesis.

Generation 3

A Generation 3 voice is built using a significantly different process compared to previous releases. The process uses new algorithms for voice creation and synthesis.

The Generation 3 voices vary in size from 250 MB to 370 MB depending on the language and speaker. In spite of the size increase, performance is comparable to that of the previous release.

4.0 Installation Instructions

If you are using the evaluation version for IBM Text-to-Speech, it will expire within 60 days after installation of the product. If you plan to use IBM Text-to-Speech beyond the trial period, please contact your IBM Representative.

End Users

Run setup.exe from the installation media and follow the instructions on the screen. You might be prompted to install concatenative voices. Select the voices to be used with concatenative voice synthesis.

ISVs

If you are deploying applications using the Text-to-Speech Run Time Kit, you must obtain a license from IBM for redistribution.

In addition, you will want to integrate our product installation with your product`s installation program. You will need to copy the redistributable TTS driver to your installation media, and invoke setup.exe.

The Text-to-Speech Run Time Kit installation program setup.exe takes the following command line arguments:

setup.exe [installPath] [/silent] [/hideaddremove] [/nr] [/ns] [/nl] [/nk] [-SMS] [/statusnone] [/statusold] [/concatall] [/concatnone] -lXXXX

-l (Lower Case L) requires the the following XXXX language code

0003-Catalan 0005-Czech 0006-Danish 0007-German
0008-Greek 0009-English 000a-Spanish 000b-Finnish
000e-Hungarian 0010-Italian 0011-Japanese 0012-Korean
0013-Dutch 0014-Norwegian 0015-Polish 0019-Russian
001a-Croatian 001b-Slovak 001d-Swedish 001e-Thai
001f-Turkish 0021-Indonesian 0024-Slovenian 002d-Basque
0404-Chinese (Taiwan) 040c-French (Standard) 0416-Portuguese (Brazilian) 0804-Chinese (PRC)
 0816-Portuguese (Standard) 0c0c-French (Canadian)    

Note: Due to an InstallShield(R) limitation, if you are using DoInstall, you must specify the same language as the parent installation. (For more information, see InstallShield document Q144122.)

<Installpath> can contain spaces and is a fully qualified path. No quotes should be placed around the path. Path will be ignored if TTS is already on the system. If a path is provided on the command line, the "Choose Directory" dialog will not be shown.

/silent
Prevents everything except the path dialog from appearing. If voice data is detected, it too will ask which voices to install, regardless of this parameter.

/hideaddremove
Deletes the Add/Remove program entry from the control panel.

/nr
Specifies no reboot message and subsequent reboot. If a calling application executes our install with a GUI, the calling install might perform additional logic. The calling install should then reboot if TTS requests. For more information on where reboot information is recorded in the registry, see the IBM Text-to-Speech SDK. TTS functionality will not work until the requested reboot is carried out. If the /silent option is used, /nr is redundant.

[-SMS]
Prevents a network connection and setup.exe from closing before the installation is complete. The switch works with installations originating from a Windows NT server over a network. Note that SMS is case-sensitive and must be uppercase.

/statusold
By default, the TTS install shows a large progress-bar dialog box. Use the this option to display the small dialog box.

/statusnone
Turns off the status box altogether.

/concatall
Installs all concatenative voices. Check return codes for "out of space."

/concatnone
Installs none of the concatenative voices.

[Redundant, but still supported for backwards compatibility]
/nk do not hide add remove (now default behavior)
/nl no license (no license now packaged).
/ns (silent install)

Note: The language parameter is not optional. A minimal amount of change is required to make old installations work.

5.0 Working with Concatenative Voices

During installation, you can install concatenative voices from the selection presented to you. Due to disk space issues, periodic updates, or business reasons, you might want to add, remove, or relocate a concatenative voice.

inivoice

The inivoice tool registers and unregisters Concatenative text-to-speech voices.

Usage: inivoice [-u] <voicenumber> <path to voice>

where:

-u Uninstall the specified voice.
voicenumber Voice number (For use with ECICopyVoice API).
path Fully qualified path to voice synthInfo file.

To add a voice, re-run the installation selecting the voice you wish to add, which runs inivoice.exe.

To remove a voice, you must unregister the voice using inivoice, and then manually delete it from the directory, such as:
<INSTALLATION DIRECTORY>\voices\<LANGUAGE> \1at08KHz_1_0
(where: "1" is the voice number, " 08KHz" is the sample rate, and "1_0" is the language code).

To relocate a voice or update a voice from a downloaded file, you must register the location of the voice using the inivoice.exe utility:
inivoice.exe [-u] <VOICENUMBER> <QUALIFIED PATH TO SYNTHINFO FILE>

For example, to move voice 1 from TTS`s default installation path to F:\TTSVoices\us\1at08KHz_1_0, move the data files and then invoke the following command:
C:>inivoice.exe 1 "F:\TTSVoices\us\1at08KHz_1_0\synthinfo"

To unregister a voice with the system use the -u command:
C:>inivoice.exe -u 1 "F:\TTSVoices\us\1at08KHz_1_0\synthinfo"

Note: Concatenative voices allow the following parameters to be adjusted at run time:

  • Volume
  • Pitch Baseline*
  • Speed
  • Pitch Fluctuation*
  • Word emphasis*

* Applies only to some voices

The following parameters and annotations are not supported for concatenative voices:

     Voice characteristics that are ignored:

  • Head Size
  • Roughness
  • Breathiness
     

      Additional annotations that are not supported:

  • Word tone
  • Phrase-Final Intonation
     

The following parameters cause the voice to be switched:

  • Gender
  • Sample Rate (see section 1 above)
  • Language
     

If a change is executed to one of the ignored parameters (listed above), no error will occur and the voice synthesis will not change.

In concatenative TTS, when you change languages, the voice characteristics are set to the default values for the currently active voice. As a result, if you`ve modified the speed or volume and you change languages, the speed and volume will revert to the default for the voice.

FAQs

Q: Why is my application still synthesizing with formant synthesis?

A: When you install an 8 kHz voice the system will produce concatenative synthesis for any application which requests synthesis at 8 kHz. By default the system generates audio at 11 kHz. In order to produce concatenative speech use eciSetDefaultParam or eciSetParam to set the sample rate.

10.0 Memory and Performance Tools

Due to the computational complexity and amount of memory required to produce concatenative speech, IBM Text-to-Speech utilizes shared memory and speech caching to reduce the amount of system resources required.

  • The concatenative TTS engine requires more physical memory (to store the data required to produce natural speech synthesis) than formant synthesis. Since many processes on a server may require access to the same data, TTS loads and shares one instance between all the processes. In addition, TTS allows configuration of how long voice data will remain loaded after the last access. By default, each concatenative voice remains loaded for 10 minutes. To configure and stop sharing the memory the Concatenative Memory Manager (CMM) utility, cmmcmd.exe, is provided. For more information on the CMM Utility, run the cmmcmd command.
     
  • The concatenative TTS engine requires more computational power than formant TTS engine. Since the domains of many TTS applications are limited to a small vocabulary, Text-to-Speech now provides a mechanism (speech caching) to bypass complex computations for text which has already been processed. The concatenative system can be configured, per language, to set a number of phrases `to remember` as pre-synthesized phrases. In addition, the memory can be made persistent (that is, saved on exit and reloaded at voice initialization). This mechanism can be beneficial in environments in which the text that is synthesized is very repetitive.
    By default caching is turned on at installation and the location of the cache file is \Program Files\viavoicetts\<language>\<voicename>\cache on Windows.
    To enable and configure speech caching, the utility inicache.exe is provided:

inicache

The inicache tool enables and configures speech caching.

Usage: inicache [-d] [-l <language>] [-r <sample rate>] [-v <voice>] -p <path>]
           [-s <persistent>] [-h <phrases>] [-u <dual language>] [-x][-b <bytes>]

where:

-d Displays current values (may only specify language, sample rate, or voice)
-l <language> is the language dialect:

1.0 - US English
1.1 - British English
2.0 - Castilian Spanish
2.1 - Mexican Spanish
3.0 - Standard French
3.1 - Canadian French
4.0 - Standard German
5.0 - Standard Italian
6.0 - Mandarin Chinese (Simplified)
6.1 - Taiwanese Chinese (Traditional)
7.0 - Brazilian Portuguese
8.0 - Standard Japanese
9.0 - Standard Finnish
10.0 - Standard Korean
11.0 - Standard Cantonese
11.1 - Hong Kong Cantonese
13.0 - Standard Norwegian
14.0 - Standard Swedish
15.0 - Standard Danish
-r <sample rate> is the sample rate:
       0 = 08 kHz (Default)
       1 = 11 kHz
       2 = 22 kHz
-p <path> is the fully qualified path to the cache file.
-v <voice> is the voice number (1, by default).
-s <persistent> is the cache file saved:
       0 = No (default setting)
       1 = Yes
-h <phrases> is the maximum number of phrases to cache (100, by default).
-u <dual language> is the cache for the dual language (if applicable).
       0 = No (default setting)
       1 = Yes
-x Removes caching for specified language.
-b <bytes> is the maximum size of the cache file in bytes.

 Notes:

  • Paths that include spaces must be enclosed in double-quotes.
  • If the -r, -u, or -v options are specified, a path must also be included.
  • Specify either the number of phrases or a maximum cache size in bytes, but not both.
  • Please refer to the documentation for valid language/dialect values.

Examples:

inicache -p "C:\Program Files\ViaVoiceTTS\voices\En_US\1at08KHz_1_0\cache"

inicache -h 5000 -u 1 -s 0 -l 6.0 -p "C:\Program Files\ViaVoiceTTS\voices\En_US\1at08KHz_1_0\cache"

inicache -l 2.0 -v 2 -r 1 -p "C:\Program Files\ViaVoiceTTS\voices\En_US\1at08KHz_1_0\cache"

11.0 Logging Utilities

A logging utility, inilog, is included in this release. Inilog replaces initrace from earlier releases.

Logging is automatically turned on when the product is installed. By default, this log is written to \Program Files\viavoicetts\tts.log on Windows.

Users and developers have the ability to customize the format of the log or the location of the log via inilog. This utility can be used to view the current settings and to modify them.

inilog

The inilog utility can be used to customize the format or location of the log, as well as to view the current settings and modify them.

Usage: inilog -d
           inilog [-f <filter>] [-l <level>] [-p <path>] [-c <comps>]

where:

-d Displays current settings (any other options will be ignored).
-f <filter> is the filter mask:

D = Data and Time (Default)
P = Process ID
T = Thread ID
C = Component name (Default)
F = Function/Method name (Default)
I = Source file name
L = Source Line number

-l <level> is the logging level:

0 = No logging
1 = Error only (Default)
2 = Warning + Error
3 = Trace + Warning + Error
4 = Debug + Trace + Warning + Error

-p <path> is the fully qualified (absolute) path to the desired location of the tts.log file (current working directory, by default).
-c <comps> is a list of components and levels to be logged.

Notes:

  • Paths that include spaces must be enclosed in double-quotes.
  • To reset filter (-f) or component (-c) to undefined, specify: "".

Examples:

inilog -p "C:\Program Files\ViaVoiceTTS\log"
inilog -l 2 -f DCF
inilog -c eci:4,cmm:2,tor:2

For example, inilog -f DC produces log files containing the date, time and component name.

inilog -c <component>:<loglevel> -- to modify the log level for certain components. The following are the valid component names:
     eci, torr, cmm, eti

Multiple components can be specified separated by a comma. For example, inilog -c eci:4,cmm:2 modifies the log level of eci to 4 and the log level of cmm to 2.

The default logging is level 1 with format DCF (date, time component and function name).
